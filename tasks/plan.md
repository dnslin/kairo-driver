# 按工号发送文本实施计划

## 目标与契约

在 `feature/send-text-to-user` 实现 `sendTextToUser(loginName, text, options?: SendToUserOptions): Promise<SendResult>`。`loginName` 是精确 `login_name`，不是显示名、UID或会话名称；仅去掉首尾空白。选项只含 `operationId` 和 `verifyTimeoutMs`。成功返回正式 `sessionId`、`messageId` 和既有业务回执，Driver 提供绑定正式会话的 `recall()`。原有按会话和媒体接口不变。

当前包未发布，没有已确认的外部数据迁移或滚动部署约束。不增加兼容层、依赖、批量调度、重试或空会话创建接口。

- 不依赖可见会话、编辑器或切窗口；准确工号目标可首次发送，sent包含正式sessionId。

- 原生业务失败不判sent；本次负草稿、接收对象与正式会话不符不得确认；unknown不重发。

## PR #13 审计修复计划

本轮修复审计提出的五项问题，不提交、推送、合并或发布。现有公开方法、Store形状和原生协议不变，不增加缓存、重试、兼容层或人员搜索替代路径。

### 搜索耗时判断

审计中的每页3.5秒为模拟延迟，不是真机性能测量。现有 `unionSearch` 是模糊搜索，SDK每页200人串行查完并精确匹配，以发现后页不同UID的同工号；耗时会随页数累加。前序准确查询接口实测失败，不用它替代已验证协议，也不在找到首个匹配时提前发送。本轮限制任务存活时间，不宣称提升原生搜索速度。

### 修复切片与验收

1. **整轮截止与取消**（`renderer-script.ts`、`message-ops.ts`、工号SDK回归）：给工号发送的渲染任务设置 `verifyTimeoutMs + 18000ms` 截止时间，早于原有外层 `verifyTimeoutMs + 20000ms`；超时中止在途IPC，最终清理定时器与登记。未提交时返回前置失败，已提交且证据不足保持unknown。慢分页超期及迟到回复不能再建草稿或发送；正常业务等待和其他实例不受影响。
2. **精确状态恢复**（`send-status.ts`、工号SDK回归）：使用已采集成功回执中的正式消息ID调用 `getMessageByMsgId`，核对本次标记、会话和双方UID；被后续消息挤出最新100条仍能恢复，错记录不能确认，查询失败保留诊断，查询/重复均不再发送。
3. **纯文本选项隔离**（`message-ops.ts`、工号SDK回归）：入口只复制operationId/verifyTimeoutMs，复用普通SendOptions不能产生提及、引用或会话目标污染；空正文仍前置失败，与Fake一致。
4. **Fake正式会话一致性**（`fake-driver.ts`、Fake回归）：自定义成功行为给出正式会话时以该ID创建或复用模拟私聊，保持结果、回执、历史和撤回目标一致；无正式ID的既有成功模式继续分配模拟ID，不制造历史或回声。
5. **示例失联退出**（专项示例及必要测试辅助模块、回归）：Driver失联而独立连接可用时，取消并等候本次操作，清理本代Hook和采集；不能取消其他操作或清理其他代的桥接。保留授权身份核对、确认门禁、unknown不重发和错误记录。

R5整合时确认本代Hook的 `receiptWaiters` 只借用发送任务的回执监听，却在cleanup中主动移除全部监听。这会破坏同Hook下其他操作，直接阻断本次“只取消本次key”验收。追加最小修正：保留发送任务自己的监听生命周期，Hook只清除观察登记；加强同Hook两项真实发送任务的取消/回执回归，不绕到Hook安装前来缩小验收。

前三项共享生产与测试文件，由主代理顺序实施；Fake和示例为独立切片，可并行修改各自文件。所有子任务跳过中途构建/测试/lint，由主代理统一执行定点失败回归、修复后回归、实际生成脚本烟测和最终 `pnpm check`。随后同步现有README、开发和启动说明及本计划清单。

真机仅执行无发送、无撤回、无会话操作的授权只读核对；没有实际执行的故障注入与收发场景明确标为未验证，不把替身回归当作真机证明。新增回归使用模拟时钟，不添加真实等待。LSP references本轮仍因语言服务退出不可用，改以既有调用路径与行为回归核对，不记为导航成功。
