### 修复切片与验收

1. **整轮截止与取消**（`renderer-script.ts`、`message-ops.ts`、工号SDK回归）：给工号发送的渲染任务设置 `verifyTimeoutMs + 18000ms` 截止时间，早于原有外层 `verifyTimeoutMs + 20000ms`；超时中止在途IPC，最终清理定时器与登记。未提交时返回前置失败，已提交且证据不足保持unknown。慢分页超期及迟到回复不能再建草稿或发送；正常业务等待和其他实例不受影响。
2. **精确状态恢复**（`send-status.ts`、工号SDK回归）：使用已采集成功回执中的正式消息ID调用 `getMessageByMsgId`，核对本次标记、会话和双方UID；被后续消息挤出最新100条仍能恢复，错记录不能确认，查询失败保留诊断，查询/重复均不再发送。
3. **纯文本选项隔离**（`message-ops.ts`、工号SDK回归）：入口只复制operationId/verifyTimeoutMs，复用普通SendOptions不能产生提及、引用或会话目标污染；空正文仍前置失败，与Fake一致。
4. **Fake正式会话一致性**（`fake-driver.ts`、Fake回归）：自定义成功行为给出正式会话时以该ID创建或复用模拟私聊，保持结果、回执、历史和撤回目标一致；无正式ID的既有成功模式继续分配模拟ID，不制造历史或回声。

## 只读人员搜索实施计划

本节方案已实施并完成代码检查与两样本真机只读验收；上文已完成工作的记录保留。具体结果与未真机验证边界见文末实施记录。

### 范围与依据

- 仅增加人员搜索，不实现中文对话、候选序号、选择记忆、会话创建或消息发送。
- 当前 `BridgeOrgOps` 已承载组织与档案查询；新能力放在同一模块，复用 `callIpcToData`，不增加服务层或依赖。
- 现行工号发送已经使用 `unionSearch({ type: 'user', kwd, pageNo, pageSize: 200 })`；采用同一原生搜索来源，不从可见组织全集或会话列表推断公司人员。
- `parseEmployee` 缺工号时回退 UID，且姓名也存在展示回退。搜索候选采用专用小类型，直接读取原生档案字段，不改变原有档案/展示接口。
- 这是新增公开方法，无持久化数据变化或已确认的迁移需求；现有发送与查询契约保持不变，不增加兼容层。

### 建议公开契约

```ts
interface KK9EmployeeSearchItem {
  id: string;
  name: string | null;
  loginName: string | null;
  departmentPaths: string[] | null;
}

interface KK9EmployeeSearchResult {
  employees: KK9EmployeeSearchItem[];
  hasMore: false;
}

searchEmployees(keyword: string, timeoutMs?: number): Promise<KK9EmployeeSearchResult>;
```

- `id` 对应真实 UID，规范为字符串，供去重和候选绑定；沿用 Driver 的 `id/loginName` 命名，`loginName` 只来自原生 `login_name`。
- `name` 只来自真实姓名；姓名或工号缺失返回 `null`，不生成姓名、不用 UID/别名工号替代。缺工号候选仍保留，调用方不能拿 UID 调用 `sendTextToUser`。
- `departmentPaths` 表示零条或多条真实部门完整路径，而不是职位或物理工位。缺失统一返回 `null`；调用方展示“部门未提供”。多部门成员保留全部可证实路径，不只保留第一次出现的部门。
- 关键词去首尾空白，空关键词抛出 `DriverError`；搜索匹配规则沿用原生，不另加模型判断、拼音规则或精确姓名过滤。
- 内部连续读取原生分页，按 UID 全局去重，完成后一次返回；`hasMore: false` 明确表示本次原生搜索已读完。没有公开页码、游标或跨请求搜索状态。
- 任何分页/档案失败、无效响应或总期限耗尽均抛错，不返回部分成功。无匹配正常返回 `{ employees: [], hasMore: false }`。
- 完整性只覆盖当前登录账号可搜索的本次结果，不保证全公司可见，不提供 `isUnique`，也不将模糊搜索的一条结果解释为准确姓名全公司唯一。
- 代价是宽泛关键词需要读取更多页及档案；使用与组织查询一致的整轮超时语义，不为速度提前截断或增加缓存。默认总期限拟沿用30秒，单次查询受剩余期限约束。
